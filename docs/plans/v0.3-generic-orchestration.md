# v0.3 Generic Orchestration Implementation Plan

Status: **Completed — release accepted for v0.3.0**

Specification:
[`docs/specs/v0.3-generic-orchestration.md`](../specs/v0.3-generic-orchestration.md)

## Delivery strategy

Use vertical tracer bullets and keep the v0.2 facade executable after every
slice. Each behavior begins with a failing public or contract test, followed by
the smallest implementation that passes, then refactoring behind the same
contract.

Do not perform a one-shot rewrite of `ai-workers.ps1`.

## Phase 0 — freeze the baseline

- [x] Add golden fixtures for v0.2 JSON and non-JSON behavior.
- [x] Cover legacy argument translation, default models, fallback, and exit
      codes.
- [x] Record Windows PowerShell 5.1 baseline.
- [x] Add a PowerShell 7 CI job and record any intentional host differences.
- [x] Keep existing transport, timeout, stream, cleanup, and redaction tests.

Exit criterion: the compatibility contract fails visibly if any v0.2 behavior
drifts.

## Phase 1 — runtime model and reviewed adapter catalog

- [x] Add a failing test for neutral schema v2 parsing.
- [x] Add failing tests for unknown fields, secret-like fields, shell fields,
      unsupported adapters, unsafe URLs, unsafe launcher paths, and capability
      escalation.
- [x] Add abuse-case tests proving v2 cannot redirect provider credentials to
      an arbitrary HTTPS endpoint and routes cannot default to write.
- [x] Document and test that repository-local config is never auto-loaded;
      user config, PATH, provider binaries, and provider-native profiles are
      explicit local trust boundaries.
- [x] Implement immutable normalized worker/profile/route objects.
- [x] Keep schema v1 behind the frozen compatibility facade and require an
      explicit, non-destructive migration before generic route/profile use.
- [x] Define versioned descriptors for `claude-code/v1`,
      `antigravity/v1`, and `minimax-cli/v1`.
- [x] Move provider invocation builders behind adapter plan functions.
- [x] Add adapter conformance and golden argument-array tests.
- [x] Bound config size/depth/object counts and process stdout/stderr capture.
- [x] Lock read mode as a side-effect ceiling that does not imply workspace
      access; routes request workspace capabilities explicitly.

Exit criterion: legacy execution still passes while provider knowledge is
localized to adapters and compatibility data.

## Phase 2 — first new vertical slice: direct worker run

- [x] Add a public failing test for `aiw run -Worker`.
- [x] Add stable v2 success, preflight failure, provider failure, timeout, and
      stream-timeout envelopes.
- [x] Route all adapter plans through the existing central native runner.
- [x] Enforce capability intersection and mode checks before process creation.
- [x] Preserve UTF-8 prompt transport and prompt byte limits.
- [x] Reject ordinary `.cmd`/`.bat` launchers and retain only the reviewed
      MiniMax shim exception.
- [x] Confirm prompt content is absent from argv, arbitrary env, and
      diagnostics.

Exit criterion: one configured worker can complete a structured fixture run
through the new public interface without changing legacy output.

## Phase 3 — profiles, routes, and safe fallback

- [x] Add resolution tests for explicit worker, profile, route, configured
      default, and `SELECTION_REQUIRED`.
- [x] Add deterministic skip and candidate-order tests.
- [x] Add read-only fallback tests with a shared deadline.
- [x] Add tests proving permission denial never falls back.
- [x] Add tests proving a started write process never causes another worker to
      launch.
- [x] Implement profile fallback only for stable allowlisted failure kinds.
- [x] Include skipped candidates and all started attempts in v2 results.

Exit criterion: provider priority is entirely configuration data and capability
requirements always outrank order.

## Phase 4 — inventory, validation, and migration UX

- [x] Add `catalog -Json`.
- [x] Add v2 inventory projection for `status` and `doctor` behind explicit
      `-OutputSchema 2`.
- [x] Make missing optional adapters non-fatal; fail doctor only when the
      requested/configured set is unusable.
- [x] Add no-config, non-mutating discovery of official supported CLIs.
- [x] Add `config -Action validate`.
- [x] Add non-destructive `config -Action migrate`; reject an existing

- [x] Verify all probes are local, non-billable, and credential-value-free.

Exit criterion: a new user can understand available adapters and create a
validated config without inheriting the maintainer's setup.

## Phase 6 — regression and release acceptance

- [x] Run the complete suite under Windows PowerShell 5.1.
- [x] Run the complete suite under PowerShell 7.
- [x] Run `git diff --check` and a public-file secret/machine-path scan.
- [x] Test clean install, upgrade from v0.2, migration, and guarded uninstall in
      temporary user roots.
- [x] Run independent bounded read smokes for each configured local adapter.
- [x] Install the candidate skill and compare installed/source hashes.
- [x] Open a separate fresh Codex task for global skill discovery and structured

- [x] Require explicit `COLD_START_PASS`; preserve evidence on failure.
- [x] Review the final diff for compatibility, security, and unnecessary

Exit criterion: deterministic tests, real smokes, installation evidence, and
independent cold-start acceptance all pass. Only then is `v0.3.0` eligible for
commit, tag, push, and GitHub release.

## Non-goals for v0.3

- arbitrary user-supplied command or argument templates;
- loading adapters from config, a repository, or a remote URL;
- automatic prompt-content classification;
- cross-worker retry after a write process starts;
- storing or brokering provider credentials;
- Linux or macOS support claims without separate implementation and evidence;
- a GUI or background daemon;
- silent config migration or automatic overwrite.
